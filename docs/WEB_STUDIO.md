# Веб-студия контента

Веб-интерфейс поверх того же бота: слева дерево объектов (уроки, записи, паспорта, живой чат),
справа вид контента, этап прогрева и фокус, посередине — чат. Чатов много, у каждого свой набор
объектов и свои настройки; между ними можно переключаться и продолжать диалог.

Телеграм-бот не меняется: студия только добавляет второй вход в те же данные.

Адрес: `https://studio.mironbot.ru` (меняется переменной `WEB_DOMAIN`).

---

## 1. Что нужно сделать один раз

**1. DNS у регистратора mironbot.ru:**

| Тип | Имя | Значение | TTL |
|---|---|---|---|
| A | `studio` | `144.124.239.159` | 300 |

**2. nginx и сертификат** (нужен sudo, скрипт делает всё сам):

```bash
sudo /home/appuser/dev/avatar/scripts/setup_studio_web.sh
```

Скрипт проверит, что домен указывает на этот сервер, поставит конфиг из
`deploy/nginx/studio.http.conf`, перечитает nginx и выпустит сертификат Let's Encrypt
с редиректом на HTTPS. Повторный запуск безопасен.

**3. Перезапуск бота** — студия поднимается внутри его процесса:

```bash
sudo supervisorctl restart avatar:avatar_julia
```

Ключи в `.env` (`WEB_ENABLED=1`, `WEB_SECRET`, `WEB_DOMAIN`, `WEB_HOST`, `WEB_PORT`) и миграции
026–027 уже на месте. Проверка после запуска:

```bash
curl -sS https://studio.mironbot.ru/healthz
```

Без домена студию можно открыть туннелем: `ssh -L 8800:127.0.0.1:8800 appuser@144.124.239.159`
и `http://localhost:8800`.

## 2. Вход через Telegram

1. Страница показывает список администраторов проекта: суперадмин из `SUPER_ADMIN_ID` и все из
   `bot_admins`. Имена подтягиваются из таблицы `users`, а если там пусто — из Telegram через бота
   и сохраняются.
2. Эксперт выбирает себя → бот присылает ему в Telegram шестизначный код (живёт 10 минут).
3. Код вводится на странице → браузер получает httpOnly-cookie сессии на 30 дней.

Что это даёт:

- не админ войти не может: при каждом запросе сессия сверяется с `bot_admins` и
  `SUPER_ADMIN_ID`, при снятии прав сессия удаляется;
- видно, кто работает: имя в правом верхнем углу, сессии лежат в `web_sessions`;
- расход токенов пишется в `token_usage` на telegram id вошедшего — видно, кто сколько потратил;
- чаты и черновики помечаются автором (`web_chats.created_by`).

Telegram id на странице не появляется: у каждого админа непрозрачная ссылка `ref` — HMAC от id на
`WEB_SECRET`. Попросить код для чужого аккаунта нельзя: лимит 5 кодов на админа за 15 минут и
5 попыток ввода на код.

**Аварийный вход.** Если бот не может написать админу, включается общий код:
`WEB_TOKEN_LOGIN=1` и `WEB_AUTH_TOKEN=<код>` в `.env`. Сессия выдаётся на суперадмина на 7 дней.
По умолчанию выключено.

## 3. Что внутри

| Файл | Роль |
|---|---|
| `web/server.py` | uvicorn как фоновая задача внутри процесса бота (одна база, один Chroma) |
| `web/api.py` | HTTP API, статика, вход, фоновые задачи генерации |
| `web/auth.py` | ссылки админов, коды входа, сессии |
| `web/objects.py` | дерево объектов и разбор их идентификаторов (`source:<uuid>`, `lesson:2.4`, `passport:expert`, `live:testimonial`) |
| `web/pipeline.py` | конвейер ответа: план поиска → выжимка сырья → генерация |
| `web/prompts.py` | промпты трёх стадий |
| `web/static/` | интерфейс: `index.html`, `app.js`, `style.css` (без сборки) |
| `db/sql/026_web_chats.sql` | `web_chats`, `web_chat_messages` |
| `db/sql/027_web_sessions.sql` | `web_login_codes`, `web_sessions` |
| `storage/db/web_chats.py`, `storage/db/web_sessions.py` | слой БД |
| `deploy/nginx/studio.http.conf`, `scripts/setup_studio_web.sh` | публикация на поддомене |

Студия живёт в процессе бота намеренно: Chroma нельзя безопасно открывать двумя процессами,
а так переиспользуются `rag_stack`, клиент DeepSeek, очередь обработки источников и сам бот
(для отправки кодов).

## 4. Конвейер ответа

Один ход диалога — три вызова LLM разного класса и цены.

| Стадия | Модель (env) | Что делает |
|---|---|---|
| 1. План поиска | `WEB_PLANNER_MODEL` (gpt-4o-mini) | Читает запрос, выбранные объекты, формат, этап, фокус и последние реплики. Знает структуру базы (виды материалов, уроки, типы карточек) и возвращает 2–4 поиска с фильтрами плюс подсказку, что искать в сырье |
| 2. Выжимка сырья | `WEB_DISTILL_MODEL` (gpt-4o-mini) | Читает **полные** расшифровки выбранных объектов кусками по 24 тыс. знаков и выписывает дословные выдержки с таймкодами, темы и голос аудитории. Кэш в `data/course/<id>/distill/` |
| 3. Генерация | `WEB_WRITER_MODEL` (пусто → `CONTENT_WRITER_MODEL`, deepseek) | Паспорта, формат, этап, фокус, выдержки, чанки из базы, карточки, одобренные образцы и история диалога → контент |

Если сырья меньше `WEB_RAW_INLINE_CHARS` (45 тыс. знаков), стадия 2 пропускается и расшифровка
уходит в генерацию целиком — так точнее.

Пример: практика из 120 тыс. знаков → 6 кусков → 33 выдержки → контекст 19 тыс. знаков,
весь ход около 26 секунд.

**Важно про JSON.** `deepseek-v4-flash` в JSON-режиме на больших кусках отдаёт пустой ответ,
поэтому стадии 1 и 2 работают на `gpt-4o-mini`. В `distill_source` есть запасной вызов: если
основная модель вернула пусто, кусок переразбирается на `COURSE_MINING_MODEL`.

### Порядок блоков в промпте

Статичная часть (роль, «Об эксперте», «О продукте» + запуск, паспорт голоса, формат) идёт
первой и не меняется между ходами — это даёт кэш префикса у DeepSeek. Дальше отдельным
системным сообщением — контекст задачи (фокус, этап, объекты, выдержки, чанки, карточки,
образцы), затем история диалога и новое сообщение.

Бюджет контекста — `WEB_CONTEXT_MAX_CHARS` (120 тыс. знаков). При переполнении режутся сначала
образцы, потом карточки, чанки, выдержки, и только в конце сырьё.

## 5. Золотой фонд

Под ответом есть кнопка «В золотой фонд». Она сохраняет текст как образец формата в коллекцию
`golden_examples` с метаданными: продукт, формат, этап, урок (если выбран один), автор, id чата.
Темой образца становится задача, которую эксперт написал перед этим ответом.

Дальше такие образцы сами подмешиваются в генерацию: на стадии 3 студия берёт до двух одобренных
примеров того же формата и показывает их модели как ориентир по тону и структуре. В интерфейсе
кнопка становится «✓ в золотом фонде», повторное нажатие ничего не дублирует.

Это та же коллекция, что использует бот, так что отметки из студии влияют и на черновики в
Telegram.

---

## 6. Прозрачность

Под каждым ответом есть «Что ушло в модель»: режим сырья, объекты, какие поиски построил
планировщик, сколько чанков, карточек и образцов пришло, размер контекста, модели и время
каждой стадии. Если ответ «не попал» — сначала смотреть сюда.

## 7. API

Публичные: `/healthz`, `/api/admins`, `/api/login/request`, `/api/login/verify`,
`/api/login/token`. Остальное — только с cookie сессии.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/admins` | кто может войти (имена и `ref`, без telegram id) |
| POST | `/api/login/request` | `{ref}` → бот отправляет код в Telegram |
| POST | `/api/login/verify` | `{ref, code}` → cookie сессии |
| GET | `/api/me` | имя вошедшего |
| POST | `/api/logout` | удалить сессию |
| GET | `/api/bootstrap` | продукт, форматы, этапы, дерево, чаты, настройки по умолчанию |
| GET | `/api/tree` | только дерево объектов |
| GET | `/api/sources/{id}` | карточка источника и превью сырья |
| GET | `/api/queue` | очередь обработки источников |
| POST | `/api/sync` | запустить синхронизацию Яндекс.Диска |
| GET/POST | `/api/chats` | список и создание чатов |
| GET/PATCH/DELETE | `/api/chats/{id}` | чат с сообщениями, настройки, удаление |
| POST | `/api/chats/{id}/message` | `{text}` → `{job_id}` |
| GET | `/api/jobs/{job_id}` | стадия, затем готовое сообщение |
| POST | `/api/chats/{id}/messages/{message_id}/golden` | ответ → золотой фонд |
| POST | `/api/settings` | фокус и этап по умолчанию для продукта |

Генерация идёт фоновой задачей, фронтенд опрашивает `/api/jobs/{id}` — ход не упирается в
таймаут прокси, и видно, на какой стадии процесс.

## 8. Ограничения

- Страница входа показывает имена админов (без id) — для поисковиков закрыта `noindex` и
  `robots.txt`, но это публичная информация. Коды уходят только в Telegram владельцу аккаунта.
- Объекты «живого чата» фильтруются по виду (`testimonial`, `dialog`, `expert_reply`), а не по
  конкретному чату: `chat_id` в метаданные чанков не пишется. Понадобится выбор отдельного
  чата — добавить поле в `group_rag_indexer` и фильтр в `rag/scope.py`.
- Один активный продукт (`ACTIVE_PRODUCT`), как и в боте.
- Потолок `fastapi<0.120` в `requirements.txt` обязателен: с 0.120 он требует
  `opentelemetry-api>=1.44`, а chromadb 1.5.x работает с 1.41 — иначе ломается импорт chromadb.
- Задачи генерации лежат в памяти процесса: после перезапуска бота незавершённый ход пропадает,
  сообщение эксперта в чате остаётся.
