## 1. Цель, принципы, границы

### 1.1 Цель

Бот работает как «редакция» эксперта:
- сам забирает материалы продукта: документы и записи с Яндекс.Диска проекта, видео по ссылкам (YouTube, Vimeo, Kinescope);
- один раз разбирает их в банк идей;
- регулярно готовит черновики контента для соцсетей в голосе эксперта.

Эксперт выбирает темы, правит черновики текстом или голосом и публикует.

### 1.2 Принципы

1. **Длинное читаем один раз, пишем много раз и дёшево.** Часы расшифровок один раз превращаются в карточки идей. Каждый черновик потом пишется по 1–3 карточкам, это единицы тысяч токенов.
2. **Основа знаний — урок.** Видео урока, конспект, слайды и Zoom-практики привязаны к уроку.
3. **Продукт — жёсткая граница.** Бот всегда работает в рамках одного активного продукта. Материалы других продуктов не попадают ни в поиск, ни в генерацию.
4. **Редакция, а не чат.** Бот сам приносит план и черновики, свободный диалог — дополнительный режим.
5. **Недорого и просто.** Один процесс бота (aiogram и фоновые asyncio-задачи), PostgreSQL и Chroma на диске. Никаких очередей, Redis и новых сервисов.
6. **Исходники не теряются и не портятся.** Яндекс.Диск бот только читает. Извлечённые тексты хранятся на сервере. Chroma — производный индекс, его можно пересобрать из PostgreSQL и сохранённых текстов.

### 1.3 Роли

| Роль | Как задаётся | Что может |
|---|---|---|
| Эксперт | `bot_admins` | все рабочие функции |
| Помощник / SMM | `bot_admins` | то же |
| Разработчик | `SUPER_ADMIN_ID` | всё перечисленное, а также управление админами, служебные команды и технический лог |

### 1.4 Не входит в MVP

- Автопубликация в соцсети. Публикация в Telegram-канал по кнопке запланирована на этап 5.
- Переключение продукта командой из бота (этап 5). До этого продукт меняется через `.env`.
- Генерация видео, голоса и картинок, нарезка клипов (этап 6).
- Ответы подписчикам и ученикам.
- Мини-апп (этап 5).
- Оплаты, лицензии, реферальная программа.

## 3. Продукты и жёсткий переключатель

### 3.1 Реестр продуктов

🔵 `config/products.json` лежит в репозитории, как `config/yandex_disk_sources.json`:

```json
{
  "products": [
    {"id": "mbt",         "name": "МБТ",              "aliases": ["мбт"],                 "disk_folder": "МБТ"},
    {"id": "magiya",      "name": "Курс Магия",       "aliases": ["курс магия", "магия"], "disk_folder": "Курс Магия"},
    {"id": "materinstvo", "name": "Клуб Материнство", "aliases": ["клуб материнство"],    "disk_folder": "Клуб Материнство"}
  ]
}
```

| Поле | Назначение |
|---|---|
| `id` | стабильный идентификатор латиницей. Хранится в PostgreSQL и Chroma и не меняется при переименовании продукта |
| `name` | как продукт называется в текстах и интерфейсе |
| `aliases` | для сопоставления старых метаданных (в Chroma сейчас записано имя, а не id) и для распознавания продукта в комментариях |
| `disk_folder` | папка продукта на Диске |

Особый id `_expert` — это не продукт, а общий слой эксперта: «Об эксперте» и общие посты. Он доступен при любом активном продукте.

### 3.2 Переключатель

- В `.env` задаётся `ACTIVE_PRODUCT=mbt`. При `COURSE_ENABLED=1` переменная обязательна. Если id нет в реестре, бот не стартует и пишет ошибку в лог.
- На этапах 1–4 продукт меняется правкой `.env` и перезапуском. Команда `/product` для суперадмина появится на этапе 5.

### 3.3 Что ограничивает переключатель

| Где | Правило |
|---|---|
| Синхронизация Диска | обрабатываются только `00 Эксперт/` и папка активного продукта; папки других продуктов пропускаются |
| Приём ссылок на видео | новый источник получает `product_id` активного продукта |
| Поиск в Chroma | только через шлюз 🔵 `rag/scope.py`: он всегда добавляет фильтр `product_id ∈ {активный, _expert}`, запрос без области — ошибка (§10.6) |
| PostgreSQL | у уроков, источников, карточек, планов, черновиков, паспорта голоса и настроек есть `product_id`; все выборки фильтруются по активному продукту |
| Промпты | «Об эксперте» (общий) плюс «О продукте» активного продукта; образцы из золотого фонда — сначала продукта, затем `_expert` |
| Интерфейс | активный продукт виден в `/start`, `/lessons` и заголовке плана («МБТ · план на 22–28.09») |

Старые чанки других продуктов остаются в Chroma, но при активном МБТ не видны (§10.7).

## 4. Исходные материалы и их поступление

### 4.1 Яндекс.Диск проекта

**Аккаунт и доступ**

- Под проект заводится отдельный аккаунт Яндекса.
- Бот подключается по WebDAV с логином и **паролем приложения** (Яндекс ID → «Пароли приложений»). Переменные те же, что у Кости: `YANDEX_DISK_LOGIN`, `YANDEX_DISK_PASSWORD`.
- Бот Диск только читает. Эксперт и помощник работают с ним как обычно: в вебе или в приложении.

**Структура папок.** Корень задаётся `COURSE_DISK_ROOT`, по умолчанию `/Аватар`.

```
/Аватар/
├── 00 Эксперт/                          ← общее для всех продуктов (product_id = _expert)
│   ├── Об эксперте.docx                 ← кто, подход, ценности, табу, как говорит
│   └── Посты/                           ← лучшие посты эксперта (подпапки Telegram/, Instagram/ …)
├── МБТ/                                 ← папка продукта = disk_folder из реестра
│   ├── О продукте.docx                  ← аудитория, программа, результат, цены, CTA, запуски
│   ├── Посты/                           ← посты именно про продукт (необязательно)
│   ├── Курс/
│   │   ├── Модуль 1/                    ← необязательный уровень
│   │   │   ├── Урок 1.1. Взрослая позиция/
│   │   │   │   ├── Конспект.pdf
│   │   │   │   ├── Слайды.pdf
│   │   │   │   └── видео/аудио урока — только если его нет на YouTube
│   │   │   └── …
│   │   └── Модуль 2/ …
│   ├── Практики/                        ← записи Zoom, если они на Диске («2026-09-18 Практика 2.4.mp4»)
│   ├── Эфиры/                           ← записи эфиров: видео, аудио, тексты
│   ├── Другое/                          ← материалы без урока
│   └── Архив/                           ← старые версии: не обрабатывается
├── Курс Магия/ …                        ← не обрабатывается, пока активен МБТ
└── Клуб Материнство/ …
```

Шаблоны «Об эксперте» и «О продукте» — в приложении А.

**Правила разбора путей** (🔵 `course/disk_layout.py`)

| Что | Правило |
|---|---|
| Продукт | папка первого уровня, совпадающая с `disk_folder` из реестра; `00 Эксперт/` → `_expert` |
| Урок | ближайшая папка с именем по шаблону `^Урок\s*(\d{1,2})(?:\s*[._]\s*(\d{1,2}))?\s*[.\-–—:]?\s*(.*)$` (без учёта регистра). Ключ урока — `M.N` (например, `2.4`). Если в имени только `N`, модуль берётся из родительской папки `Модуль M` (получается `M.N`), иначе ключ — просто `N`. Остаток имени — название. Если в продукте два урока с одним ключом, в служебный чат уходит ошибка и берётся первый по пути |
| Модуль | папка `^Модуль\s*(\d{1,2})…` (необязательно) |
| Конспект | имя файла содержит «конспект» |
| Слайды | имя содержит «слайд» или «презентац» |
| Доп. материал | прочие документы в папке урока |
| Видео и аудио | `.mp4 .mov .mkv .webm .m4v .avi` и `.mp3 .m4a .wav .ogg .opus .flac .aac` (§4.3). В папке урока — `lesson_video`, в `Практики/` — `practice`, в `Эфиры/` — `broadcast`, в `Другое/` — `other` |
| Практики и эфиры | дата и ключ урока берутся из имени файла («2026-09-18 Практика 2.4»); для эфиров урок необязателен |
| Посты | `Посты/` внутри `00 Эксперт/` или папки продукта; имя подпапки задаёт площадку (`telegram`, `instagram`, `vk`, …) |
| Об эксперте / О продукте | `00 Эксперт/Об эксперте.*` и `<продукт>/О продукте.*` (docx, txt, md, pdf) |
| Игнор | `Архив/`, имена с `_` или `.` в начале, неподдерживаемые форматы, папки неактивных продуктов |

- Документы: PDF, DOCX, TXT, MD.
- Нумерация «модуль.урок» совпадает с материалами МБТ в текущей базе («Урок 2.4.pdf», «Урок 1.6…»). Старые файлы вида «6. УРОК 6_МБТ_июнь 2023.pdf» (по тексту это урок 1.6) переименовывать не нужно: урок определяется папкой.
- Если по пути не понять урок файла, который к уроку относиться должен (например, практика без номера в имени), бот спрашивает эксперта в личке кнопками со списком уроков. Одно сообщение на пачку файлов.

**Синхронизация** (🟡 на основе `K/yandex_disk/webdav.py` и цикла опроса из `K/bot/features/yandex_disk_sync.py`)

- Опрос каждые `COURSE_DISK_POLL_SEC` секунд (по умолчанию 900) и по команде `/sync`. Одновременно идёт только одна синхронизация (`asyncio.Lock`, как у Кости).
- Бот рекурсивно обходит `00 Эксперт/` и папку активного продукта (`YandexDiskWebDAV.list_files(recursive=True)`) и для каждого файла получает путь, `etag`, размер и дату изменения.
- Файлы сверяются с `course_sources` (`origin='disk'`):
  - новый путь → новый источник со статусом `new`;
  - тот же путь, но другой `etag` → переобработка. Старые чанки источника удаляются, карточки архивируются, готовые черновики не трогаются;
  - путь пропал → статус `deleted`, чанки удаляются из Chroma, карточки уходят в `archived`;
  - файл с тем же `etag` и размером появился по новому пути (переименование или перенос) → обновить путь и урок без переобработки. Желательно, но не обязательно.
- Урок создаётся или обновляется по папке: ключ пишется в `course_lessons`, при переименовании папки меняется название урока.
- Полузагруженные файлы не берутся: файл уходит в обработку, только если он изменён больше 2 минут назад.
- Итог синхронизации идёт в служебный чат. Эксперту приходят только значимые события (§7.3).

### 4.2 Ссылки на видео

Отвечают модули 🔵 `bot/features/course_intake.py`, 🔵 `course/classify.py` и 🔵 `course/video_hosts/`.

**Хостинги**

| Хостинг | Ссылки | Как получаем текст | Когда |
|---|---|---|---|
| YouTube | видео, shorts, трансляции, плейлисты (🟢 `extract_youtube_urls` из `bot/media_processing/processors/youtube.py`, 🔵 плюс `list=`) | субтитры json3, при их отсутствии — Whisper (§5.2) | этап 1 |
| Vimeo | `vimeo.com/<id>`, в том числе с хешем доступа по ссылке | yt-dlp: экстрактор Vimeo есть в установленной версии 2026.03.17. Текстовые дорожки, если автор их включил, иначе аудио в Whisper | этап 1, если тестовая ссылка проходит на этапе 0; иначе этап 5 |
| Kinescope | ссылки плеера `kinescope.io/…` | в yt-dlp экстрактора Kinescope нет. Через API Kinescope по токену кабинета эксперта: ссылка на файл или аудио, субтитры, если есть. Детали — по тестовому видео на этапе 0 | этап 5 |

**Приоритет хранения** задаёт `VIDEO_HOST_PRIORITY`, по умолчанию `youtube,vimeo,kinescope,disk`.
- Основное хранилище видео — YouTube: там бесплатные субтитры и стабильные ссылки с таймкодом.
- Если у урока уже есть видео того же типа с длительностью в пределах ±2 %, бот спрашивает: «Похоже, это то же видео, что уже есть на YouTube» [Пропустить] [Всё равно обработать]. Дубль не обрабатывается, его ссылка сохраняется в `alt_urls` исходного источника.
- Ссылка с таймкодом в карточке строится по самому приоритетному хостингу источника:
  - YouTube: `https://youtu.be/<id>?t=<sec>`;
  - Vimeo: `https://vimeo.com/<id>#t=<sec>s`;
  - Kinescope: формат уточнить;
  - файл на Диске: ссылки нет, показывается «эфир 18.09 · 12:40».

**Сценарий приёма**

1. Админ присылает в личку одну или несколько ссылок. Можно добавить комментарий: «урок 2.4», «практика к 2.4».
2. Бот определяет хостинг и получает метаданные без скачивания: `yt-dlp -J --skip-download` для YouTube и Vimeo, API для Kinescope. Метаданные: название, длительность, дата, описание, главы, наличие субтитров. Плейлист — `--flat-playlist -J` с лимитом `COURSE_PLAYLIST_MAX` (по умолчанию 100).
3. Определение урока и типа:
   - сначала правила: ключ урока из комментария или названия (`урок\s*(\d{1,2})(?:[._](\d{1,2}))?`), слова «практика», «zoom», «разбор», «встреча» → `practice`, «эфир» → `broadcast`;
   - если однозначно не получилось, решает дешёвая LLM. Ей передаётся список уроков активного продукта, ответ — JSON `{lesson_key, kind, recorded_on, confidence}` (по образцу `K/yandex_disk/metadata_llm.py`);
   - возможные `kind`: `lesson_video` (запись урока), `practice` (Zoom-практика), `broadcast` (эфир), `other` (прочее видео эксперта). У урока может быть несколько видео, например части 1 и 2.
4. Карточка подтверждения:
   ```
   🎬 YouTube · «Практика к уроку 2.4» · 1:32:10 · 18.09.2026
   → МБТ · Урок 2.4 «Своё место в жизни» · Zoom-практика
   [✅ Верно] [📚 Другой урок] [🔁 Тип] [✖ Отмена]
   ```
   Несколько ссылок или плейлист показываются одним нумерованным списком с кнопками [✅ Всё верно] и [✏️ Исправить №…]. Длинный список разбивается на несколько сообщений. Перед массовой обработкой бот показывает оценку объёма и стоимости (§5.8).
5. После подтверждения создаётся источник (`origin` — хостинг, `status='new'`, `product_id` — активный продукт). Та же карточка редактируется по ходу работы: «⏳ в очереди» → «📝 расшифровка» → «🧠 разбор» → «✅ готово: 41 карточка».
6. Если ссылка уже обработана (совпадают хостинг и `video_id`), бот отвечает «уже в базе (урок 2.4, 12.09)» и предлагает кнопку [🔁 Переобработать].
7. Если урока с таким ключом ещё нет, бот предлагает создать его в БД с названием из видео. Когда на Диске появится папка с этим ключом, урок свяжется с ней автоматически.

Реестр ссылок хранится в БД (`course_sources`). Посмотреть его можно командами `/lessons` и `/lesson 2.4`.

### 4.3 Видео и аудио на Диске

Видео и аудио на Диске — запасной вариант хранения. Типичный случай — записи эфиров.

- Где лежат: папка урока (видео урока), `Практики/`, `Эфиры/`, `Другое/`.
- Обработка (🔵 `course/video_hosts/disk_media.py`):
  1. длительность через ffprobe (🟡 `probe_media_duration_sec` из `K/telemost_mail/webdav_recording.py`);
  2. скачивание во временную папку (🟢 `YandexDiskWebDAV.download`, потоковая запись);
  3. извлечение звука: моно, 16 кГц, 32 кбит/с (🟡 `_extract_audio_from_video_file` из `K/telemost_mail/webdav_recording.py`, `_compress_audio_for_whisper` из `K/openai_client/assistant.py`);
  4. Whisper с таймкодами (§5.2);
  5. временные файлы удаляются.
- Субтитров у файлов нет, поэтому расшифровка всегда платная (около $0,36 за час). Перед массовой обработкой показывается оценка (§5.8).
- Лимит размера — `COURSE_MEDIA_MAX_GB` (по умолчанию 4 ГБ), временные файлы — в `COURSE_TMP_DIR`.
- Если то же видео уже есть на хостинге с более высоким приоритетом (тот же урок и тип, длительность ±2 %), файл с Диска не обрабатывается.

### 4.4 Закрытые видео

- YouTube с доступом по ссылке и Vimeo со ссылкой-хешем обрабатываются как публичные.
- Закрытые видео YouTube и Vimeo — этап 5, если понадобится:
  - cookies аккаунта, у которого есть доступ (`YTDLP_COOKIES_FILE`);
  - или API от имени владельца. Для YouTube это `captions.download` со scope `youtube.force-ssl`; OAuth-обвязку можно адаптировать 🟡 из `K/scripts/youtube_oauth_setup.py` и `K/youtube_prayer/youtube_uploader.py`, но сейчас там есть только scope `youtube.upload`. Для Vimeo — токен владельца `VIMEO_ACCESS_TOKEN`.

## 5. Обработка источников

### 5.1 Конвейер и статусы

🔵 `course/worker.py` — один фоновый воркер внутри процесса бота. Запускается из `start_background_tasks`, как фичи у Кости. Работает только с источниками активного продукта и `_expert`.

```
new → fetching → extracted → indexed → mining → done
          └──────────┴───────────┴────────┴──► error (attempts, error_message) → повтор
deleted · skipped
```

- Очередью служит сама таблица `course_sources`: воркер выбирает записи по `status`, `next_attempt_at` и `created_at`. Внешние брокеры не нужны.
- Параллелизм: скачивание и расшифровка идут по одной; LLM-разбор — до `COURSE_LLM_CONCURRENCY` вызовов одновременно (по умолчанию 3).
- После рестарта источники, зависшие в `fetching` или `mining` дольше 30 минут, возвращаются на предыдущий шаг.
- Повторы: до 3 попыток с паузами 5, 30 и 120 минут. Затем статус `error`, сообщение в служебный чат и кнопка [🔁 Повторить] в `/queue`.
- Каждая стадия сохраняет результаты в `data/course/<source_id>/`:

| Файл | Содержимое |
|---|---|
| `meta.json` | метаданные хостинга или Диска |
| `transcript.json` | сегменты `[{start, end, text}]` и способ получения (`subs` / `whisper`) |
| `pages.json` | текст PDF по страницам и признак «страница без текста» |
| `slides/page-NNN.png` | PNG слайдов |
| `mining.raw.jsonl` | сырые ответы LLM: для отладки и повторного разбора без новых вызовов |

- Повторный разбор идёт из сохранённого текста: `/remine <source|lesson>`, только для суперадмина.

### 5.2 Видео → расшифровка с таймкодами

Отвечают 🔵 `course/video_hosts/` (адаптеры), 🔵 `course/subtitles.py` и 🟡 `course/transcribe.py`.

**Интерфейс адаптера хостинга**
- `probe(url)` → метаданные;
- `fetch_subtitles()` → сегменты или `None`;
- `fetch_audio()` → путь к аудиофайлу;
- `timecode_url(sec)` → ссылка с таймкодом.

**Реализации адаптера**
- `ytdlp.py` — YouTube и Vimeo;
- `disk_media.py` — файлы на Диске (§4.3);
- `kinescope.py` — этап 5.

**Порядок получения текста**

1. **Субтитры** (бесплатно):
   - YouTube: `yt-dlp --skip-download --write-subs --write-auto-subs --sub-langs "ru,ru-orig,ru.*" --sub-format json3`. Ручные субтитры предпочтительнее автоматических. json3 разбирается в сегменты по полям `events[].tStartMs`, `dDurationMs`, `segs[].utf8`; в нём нет «бегущих» повторов, как в VTT;
   - Vimeo: те же флаги yt-dlp; текстовые дорожки обычно в VTT, при разборе повторы удаляются;
   - Kinescope: субтитры через API, если они есть (этап 5);
   - Диск: субтитров нет.
2. **Проверка качества.** Если субтитров нет или их плотность ниже `COURSE_SUBS_MIN_CHARS_PER_MIN` (по умолчанию 300 знаков в минуту), используется Whisper.
3. **Whisper с таймкодами:**
   - аудио берётся через адаптер: yt-dlp (🟢 `download_youtube_audio` из `processors/youtube.py`), с Диска или через API;
   - ffmpeg режет его на куски по 10 минут (🟡 `_transcribe_in_segments` оттуда же);
   - запрос к `whisper-1` с `response_format="verbose_json"` и `timestamp_granularities=["segment"]`, таймкоды сдвигаются на смещение куска;
   - новый метод `OpenAIClient.transcribe_segments()` пишется рядом с `transcribe_voice`. Основа — 🟢 версия `K/openai_client/assistant.py` с `_compress_audio_for_whisper`. Расход пишется в `token_usage` через `_log_llm_metrics`.
4. Режим выбирается переменной `COURSE_TRANSCRIBE_MODE`: `auto`, `subs` или `whisper`.
5. Результат — список `SpeechSegment`. Взять 🟢 из `K/telemost_mail/timestamped_speech.py` (`SpeechSegment`, `merge_segments_window`, `format_expert_blocks_for_prompt`); в заготовке лежит старая версия этого файла.
6. yt-dlp вызывается как `sys.executable -m yt_dlp` (как у Кости). Можно передать `YTDLP_COOKIES_FILE`. При каждом деплое выполняется `pip install -U yt-dlp`: YouTube часто ломает старые версии.

Ни субтитры, ни Whisper не разделяют речь по спикерам. В практиках эксперта и участников различает LLM на этапе разбора по смыслу; имя эксперта передаётся в промпт (`EXPERT_NAME`).

### 5.3 Документы → текст

🟡 `course/documents.py` на основе `bot/media_processing/processors/document.py`:

- **PDF:** `pdftotext -layout` с разбиением по страницам (по символу `\f`), результат в `pages.json`.
- **Слайды:**
  - дополнительно `pdftoppm -png -scale-to 1280`, результат в `slides/page-NNN.png`;
  - если на странице меньше 20 символов текста, она распознаётся через vision: 🟢 `describe_image` из `openai_client/assistant.py`, модель `gpt-4o-mini`, промпт «перепиши текст слайда и кратко опиши схему или картинку»;
  - лимит — `COURSE_VISION_MAX_PAGES` страниц на файл (по умолчанию 80).
- **Скан-PDF без текстового слоя:** тот же путь через vision и тот же лимит.
- **DOCX:** 🔵 через `python-docx` (уже есть в `requirements.txt`). Текущий `_extract_text_from_doc` на Linux с .docx не работает: catdoc читает только .doc, а textutil есть только в macOS.
- **TXT и MD:** кодировка UTF-8, запасная — cp1251.
- **Посты:** если в одном файле несколько постов, они делятся по разделителям (`---`, `***`, три и больше пустых строк). Фрагменты короче 200 символов отбрасываются.
- poppler и ffmpeg на сервере уже установлены.

### 5.4 Индексация чанков

Берём 🟢 `rag/material_index.py` с 🟡 доработками. Подробная схема — §10.

- Метаданные v2 с `product_id`, `source_id`, `lesson_key` и таймкодом или страницей (§10.4).
- Нарезка без разрыва предложений, у видео — окна по времени. В тексте каждого чанка — короткий заголовок «продукт · урок · вид · таймкод/страница» (§10.5). Для видео 🟡 нужна новая функция `add_segments_text()` рядом с `add_material_text`.
- 🔵 `delete_by_source(source_id)` (`collection.delete(where={"source_id": …})`) — для переобработки и удаления.
- Соль для защиты от дублей: `course:{source_id}:{etag|video_id}`.
- 🟢 Из `K/` нужно перенести `truncate_for_embedding` (`K/rag/embeddings.py`) и его вызовы. Без этого длинные запросы падают с ошибкой 400.

### 5.5 Разбор: карточки идей

🔵 `course/mining.py`. Основа — 🟡 функции из `K/telemost_audio/reels_director.py`: `_split_expert_blocks`, `_call_openai_messages`, `_parse_json_obj`, `_ideas_similar`, `_merge_ideas`, `_window_for_idea`, `_verbatim_hits`.

**Шаг 1: извлечение (map).** Текст источника режется на куски примерно по 20 000 знаков. Видео — блоками `[A–B s]` через `format_expert_blocks_for_prompt`, документы — по страницам. Каждый кусок уходит в `COURSE_MINING_MODEL` в JSON-режиме. Промпт зависит от `source_kind`: урок, практика, эфир, конспект, слайды, другое. Схема ответа:

```json
{"cards": [{
  "type": "idea|quote|story|metaphor|myth|mistake|exercise|question|pain|insight|case",
  "title": "до 80 знаков",
  "text": "суть в 2–5 предложениях",
  "quote": "дословно 1–2 предложения из куска или пусто",
  "anchor_sec": 754.0,
  "page": null,
  "speaker": "expert|participant",
  "audience_pain": "какую боль или запрос закрывает, коротко",
  "funnel_stage": "reach|warmup|sale",
  "formats": ["tg_post", "reels", "carousel", "stories"],
  "score": 0
}]}
```

**Правила промпта:**
- брать только то, что есть в куске;
- `quote` — дословная цитата;
- участники обезличены («участница», «один из участников»): никаких имён, городов, профессий и других узнаваемых деталей;
- организационные реплики («меня слышно?») пропускать;
- не додумывать факты и не обещать результатов.

**Шаг 2: сведение (reduce):**
- дубли внутри источника склеиваются (🟡 `_ideas_similar`), остаются лучшие по `score`: до `COURSE_CARDS_PER_HOUR` на час видео (по умолчанию 30) и до 15 на документ;
- дубли между источниками ищутся через коллекцию `content_cards`, в пределах активного продукта. Если у новой карточки типа `question`, `pain` или `insight` есть похожая из другой практики (косинус ≥ `COURSE_CARD_DUP_SIM`, по умолчанию 0,88), новая карточка не создаётся. Вместо этого у существующей растёт `frequency`, а источник добавляется в `related_source_ids`. Вопросы, которые повторяются от практики к практике, — сильные темы для контента;
- цитата проверяется на дословность (как `_verbatim_hits` у Кости): нормализованный `quote` должен находиться в тексте куска, иначе поле очищается;
- таймкод превращается в ссылку через `timecode_url()` адаптера хостинга (§5.2).

### 5.6 Паспорт урока

🔵 `course/mining.py::build_lesson_passport`.

Паспорт пересобирается через `COURSE_PASSPORT_DEBOUNCE_SEC` секунд (по умолчанию 600) после последнего изменения источников урока. Задержка нужна, чтобы при массовой загрузке он не собирался десять раз.

**Вход:** полный текст конспекта и слайдов, топ-карточки урока (заголовок и суть).

**Выход** (JSON, из которого собирается текст):
- главная мысль урока (1–2 предложения);
- 5–10 ключевых идей;
- термины и модели (термин → определение);
- упражнения и практики;
- истории и метафоры;
- типичные ошибки и мифы;
- боли аудитории, которые закрывает урок;
- что человек получает после урока;
- ссылки на видео урока и практики.

### 5.7 Паспорт голоса и золотой фонд

🔵 `course/style.py`.

- **Вход:**
  - посты из `00 Эксперт/Посты/` и `<продукт>/Посты/` (площадка берётся из подпапки);
  - «Об эксперте» и «О продукте»;
  - 5–10 случайных блоков речи эксперта из уроков;
  - правила, накопленные из 👎.
- **Выход:** markdown с фиксированными разделами:
  1. Кто говорит: позиционирование и роль.
  2. Аудитория продукта и её язык.
  3. Тон и манера: 3–5 признаков с примерами из постов.
  4. Словарь: характерные слова и обороты. Отдельной строкой `Запретные: слово1, слово2, …` — её разбирает проверка после генерации (§6.2).
  5. Структура постов по площадкам: зачины, длина, абзацы, эмодзи, хэштеги.
  6. CTA и продукт (как в «О продукте»).
  7. Табу и ограничения.
  8. Правила из обратной связи.
- Модель — `STYLE_MODEL`. Можно выбрать сильную: вызов редкий.
- Паспорт хранится по продукту (`style_profiles.product_id`) с версиями. Он пересобирается автоматически при изменении файлов в `00 Эксперт/`, а также файла «О продукте» и папки `Посты/` активного продукта.
- Если эксперт загрузил свою версию, автопересборка её не перезаписывает. Новые правила из 👎 дописываются в раздел 8, остальное не меняется.
- «Об эксперте» и «О продукте» попадают в промпт генерации **дословно**: цены, ссылки и названия должны быть точными. Лимит — `COURSE_INFO_MAX_CHARS` на каждый файл (по умолчанию 8000). Если файл больше, в служебный чат уходит предупреждение.
- **Первое наполнение золотого фонда.** Посты сразу загружаются в `golden_examples`:
  - из `00 Эксперт/Посты/` — с `product_id=_expert`;
  - из папки продукта — с id продукта.

  Формат определяется по площадке (`Telegram` → `tg_post`, `Instagram` → `ig_post`). Так образцы работают с первого дня.

### 5.8 Оценка перед массовой обработкой

Оценка показывается в двух случаях:
- при подтверждении плейлиста или нескольких ссылок;
- при синхронизации, которая нашла больше 10 новых файлов или хотя бы одно видео или аудио.

Бот сообщает:
- сколько часов видео и у какой части есть субтитры (у файлов с Диска их нет никогда);
- прогноз расходов на расшифровку и разбор.

Работа начинается только по кнопке [▶️ Запустить]. Прогноз считается по длительности и числу знаков, цены берутся из конфига (`COST_TABLE`).

## 6. Генерация контента

Всё в этом разделе работает в рамках активного продукта (§3).

### 6.1 Форматы

🔵 `course/formats.py` описывает форматы: id, площадка, длина, структура, правила разметки. Стартовый набор (окончательный — после выбора соцсетей):

| id | Что | Требования |
|---|---|---|
| `tg_post` | пост в Telegram-канал | 800–1500 знаков; первая строка — крючок; 3–5 абзацев; вывод; CTA; Telegram-HTML (`<b>`, `<i>`, `<a>`) |
| `ig_post` | подпись к посту Instagram | до 2200 знаков; первая строка — крючок; абзацы; CTA; до 5 хэштегов; без разметки |
| `carousel` | карусель | 6–10 слайдов, не больше 25 слов на слайд; первый — крючок, последний — CTA; подпись к посту; номера подходящих слайдов курса |
| `reels` | сценарий Reels/Shorts на 30–60 с | хук не длиннее 3 с; 3–5 реплик; CTA; текст на экране; подпись |
| `stories` | серия сторис | 4–7 кадров: текст, интерактив (опрос, вопрос, слайдер), CTA |

Чтобы добавить формат, достаточно описать его в `formats.py` и при необходимости положить образец в золотой фонд.

### 6.2 Сборка промпта

Отвечают 🔵 `course/writer.py` и 🔵 `openai_client/content_prompts.py` (по образцу 🟡 `openai_client/task_rag_prompt.py`).

Порядок блоков фиксирован. Статичная часть идёт первой и **совпадает байт в байт** между вызовами: в ней нет дат и счётчиков. Тогда DeepSeek кэширует этот префикс. Продукт меняется редко, поэтому кэш не сбрасывается.

| № | Блок | Статичный? |
|---|---|---|
| 1 | Роль и общие правила: «продюсер контента», не выдумывать факты, обезличивать участников | да |
| 2 | «Об эксперте» дословно | да |
| 3 | «О продукте» активного продукта дословно | да |
| 4 | Паспорт голоса (активная версия для продукта) | да |
| 5 | Описание формата | общий для формата |
| 6 | До 2 образцов этого формата из золотого фонда: сначала продукта, затем `_expert` (через шлюз, §10.6) | нет |
| 7 | Материал: 1–3 карточки, краткий паспорт урока и окно расшифровки ±60 с вокруг `anchor_sec` (🟡 `_window_for_idea`). Окно берётся **только из записей уроков и эфиров эксперта**; для практик передаётся лишь текст карточки, потому что в окне могут звучать имена участников | нет |
| 8 | Задача: заход, цель или этап воронки, CTA. Для правки — прошлая версия и правки | нет |

- Модель — `CONTENT_WRITER_MODEL`. Вызов через 🟢 `AgentsClient.run_with_messages` (DeepSeek) или OpenAI через 🔵 `course/llm.py`. `llm.py` выбирает провайдера по имени модели, поддерживает JSON-режим и пишет расход в `token_usage`. В `AgentsClient` 🟡 модель должна браться из конфига, а не из константы `CHAT_MODEL`.
- **Проверки после генерации (без LLM):**
  - длина в пределах формата;
  - нет слов из строки `Запретные:` паспорта голоса;
  - корректный Telegram-HTML (🟢 `bot/utils/telegram_html.py`).

  При нарушении делается один повтор с конкретным замечанием. Если и он не прошёл, черновик отдаётся с пометкой.

### 6.3 Режим «План недели»

🔵 `course/planner.py` и `bot/features/content_studio.py`.

- **Запуск:** по расписанию `CONTENT_PLAN_WEEKDAY` / `CONTENT_PLAN_HOUR` в часовом поясе `CONTENT_PLAN_TZ` (по умолчанию понедельник, 09:00, Europe/Moscow) или вручную командой `/plan`. Цикл расписания — 🟡 `_daily_loop` и `_seconds_until_msk` из `K/bot/features/youtube_prayer_feature.py`.
- **Состав недели** задаёт `CONTENT_PLAN_MIX` (по умолчанию `tg_post:3,reels:2,carousel:1,stories:1`).
- **Фокус** задаётся командой `/focus <текст>`, например «прогрев к набору 1 октября». Хранится в `content_settings` активного продукта.
- **Алгоритм:**
  1. SQL отбирает около 40 кандидатов среди карточек активного продукта: активные, не использованные `CARD_REUSE_DAYS` дней (по умолчанию 60), со `score` выше порога, не больше 3 на урок. Приоритет у частых вопросов и болей из практик за последние 30 дней.
  2. Один вызов `COURSE_PLANNER_MODEL` (дешёвой модели) подбирает позиции под состав недели. Для каждой позиции: формат, 1–3 карточки, заход в одно предложение, этап воронки, день недели. Ответ в JSON.
  3. Результат записывается в `content_plans` и `content_items` (`status='planned'`).
  4. Эксперт получает нумерованный список, у каждой позиции переключатель ✅/❌. Внизу кнопки [🔄 Заменить ❌] и [✍️ Написать выбранные].
  5. По кнопке «Написать выбранные» черновики приходят по одному, прогресс отображается в сообщении плана.

### 6.4 Режим «Из свежей практики»

Когда источник `practice` или `broadcast` получает статус `done`, эксперту приходит сообщение:

```
🧩 МБТ · Практика 18.09 · Урок 2.4 «Своё место в жизни» — 6 тем для контента
1. Вопрос: «…» (звучал уже на 3 практиках)
2. …
```

Под каждой темой кнопки [📝 Пост] [🎬 Рилс] [🎠 Карусель], внизу — [📋 Все карточки].

Для нового урока приходит похожее сообщение: «Урок 2.7 разобран: паспорт + 34 карточки» с кнопками [📖 Паспорт] и [📝 Серия постов по уроку].

### 6.5 Режим «По запросу»

Основа — 🟡 `bot/features/creative_rag_coordinator.py` и `openai_client/task_rag_prompt.py` (они уже есть в заготовке).

- Любой текст или голосовое от админа в личке без команды считается задачей. Приветственного шага, как у `/new`, нет: бот сразу ищет материалы и пишет черновик. `/new` остаётся для явного сброса контекста.
- **Поиск материалов** — только через шлюз `rag/scope.py` (§10.6):
  - карточки: топ-5 по смыслу;
  - чанки: топ-5, с фильтром по `lesson_key`, если в запросе назван урок («по уроку 2.4»);
  - паспорт урока, если урок назван;
  - запрос для поиска = текст задачи и последние реплики (🟢 `build_dialogue_context_text`). Планировщик поиска `rag/retrieval_planner.py` не нужен: в нём логика для отзывов клиентов, а отзывов у нас нет.
- `AGENT_META` (🟢 `openai_client/agent_meta.py`) переделать: вместо `product/content_type` передавать `format`, `lesson_key`, `task_summary` и `is_draft`. Продукт задаётся не моделью, а переключателем. Если `is_draft=true`, ответ сохраняется как версия `content_item`, и под ним появляются кнопки из §6.6. Если `false`, это уточняющий вопрос обычным сообщением.
- Системный промпт собирается общим сборщиком из §6.2 вместо текущей универсальной персоны.
- Общий чат из `MessagingFeature._get_agent_response` для админов не нужен.

**Порядок маршрутизации в личке** (🟡 `MessagingFeature.handle_chat_message`):
1. Ожидаемый ввод по FSM (своя версия паспорта голоса, причина 👎 «Другое») → соответствующая фича.
2. Ответ (reply) на сообщение черновика → правка (§6.6).
3. В сообщении есть ссылки на видео → приём (§4.2).
4. Иначе → задача «по запросу».

### 6.6 Черновик и действия с ним

Отвечает 🔵 `bot/features/content_studio.py`. Хранение сделать 🟡 по образцу `K/storage/db/reels_scenarios.py` и `K/db/sql/027_reels_scenarios.sql`, кнопки — 🟡 по образцу `feedback_keyboard` и `parse_feedback_cb` из `K/telemost_audio/reels_director.py`, а также `K/bot/features/reels_feature.py`.

Под каждым черновиком:

```
[👍 Беру] [👎]
[🔄 Ещё вариант] [✂️ Короче] [🪝 Сильнее крючок]
[📝 В пост] [🎬 В рилс] [🎠 В карусель]
```

- **Правка.** Ответ (reply) на черновик текстом или голосом создаёт новую версию отдельным сообщением. Голос распознаёт текущий медиапроцессор. Чтобы находить черновик по reply, у версии хранятся `chat_id` и `message_ids`.
- **👍:**
  - статус черновика → `approved`;
  - текст сохраняется в `golden_examples` с `product_id` активного продукта (🟢 `rag/golden_store.py`; 🟡 `GoldenSnapshot` из `bot/features/golden_chroma_fields.py` с новыми полями `format` и `lesson_key`);
  - у использованных карточек обновляются `last_used_at` и `used_count`;
  - появляется кнопка [📌 Опубликовал].
- **👎** предлагает быстрые причины: [Не мой тон] [Вода] [Неточно по смыслу] [Длинно] [Другое — напишу].
  - Причины копятся в `content_feedback`.
  - Раз в неделю или после 10 новых причин LLM сводит их в 3–7 конкретных правил, которые попадают в раздел 8 паспорта голоса.
- **Карусель.** После текста бот присылает альбомом (до 10 штук) PNG рекомендованных слайдов курса из `data/course/<source>/slides/`.
- **Длинный текст** разбивается через 🟢 `bot/utils/telegram_chunk.py`, кнопки ставятся под последней частью.
- Формат `callback_data`: `ci:<действие>:<item_uuid>`, укладывается в 64 байта.

### 7.3 Что приходит эксперту без запроса

- План недели.
- «Из свежей практики» и «Урок N разобран» — одно сообщение на урок, а не на каждый файл.
- Проблемы, которые требуют его действий, коротко и с кнопкой. Например: видео недоступно; PDF без текста, а лимит распознавания исчерпан; не удалось определить урок файла; найден возможный дубль видео.

Всё остальное уходит в служебный чат.

### 7.4 Мини-апп

В MVP не входит. На этапе 5 — два экрана: «Банк идей» (фильтры по уроку, типу и использованию) и «Календарь контента». Техника: тот же процесс и та же БД, небольшой FastAPI со статическим фронтендом, вход через Telegram `initData`.

### 10.3 Принципы схемы v2

1. **Chroma — производный поисковый индекс.** Источник истины — PostgreSQL (`course_sources`, `content_cards`) и тексты в `data/course/`. Эмбеддинги всего курса стоят меньше $0,1, поэтому индекс можно пересобрать в любой момент, а схему — смело менять.
2. **Продукт — обязательный фильтр.** У каждой записи есть `product_id`. Читать можно только через шлюз `rag/scope.py` (§10.6).
3. **Одна коллекция на тип данных, а не на продукт:** `expert_materials`, `content_cards`, `golden_examples`. При таких объёмах фильтр по метаданным работает быстро, а общий слой `_expert` делается одним условием `$in`.
4. **Метаданные плоские и только для фильтров и ссылок.** Тексты хранятся в PostgreSQL. Исключение — текст образца в `golden_examples`: он остаётся в метаданных, как сейчас в `golden_store.py`.
5. **Поле `legacy` пишется у всех записей** (`false` у новых). Иначе фильтр `{"legacy": {"$ne": true}}` отсечёт записи, у которых этого поля нет.
6. **Метрика.** Новые коллекции (`content_cards` и пересоздаваемая `golden_examples`) создаются с косинусной метрикой (`hnsw space = cosine`). `expert_materials` остаётся на L2 до полной пересборки. Эмбеддинги OpenAI нормированы, поэтому порядок выдачи тот же, а пороги пересчитываются по формуле `cos = 1 − d/2` (в Chroma L2 — это квадрат расстояния).

### 10.5 Нарезка чанков и сборка контекста

- **Документы:** страница → абзацы → предложения. Предложения упаковываются в чанки примерно по 500–700 токенов без разрыва; перекрытие — 1–2 предложения.
- **Видео:** окна по времени (около 2–3 минут, до ~600 токенов) с таймкодами в тексте.
- **Заголовок в тексте каждого чанка:** `[МБТ · Урок 2.4 «Своё место в жизни» · конспект · стр. 3]` или `[МБТ · Урок 2.4 · видео урока · 12:40–15:10]`. Он улучшает поиск и показывает модели, откуда фрагмент.
- **Сборка контекста:**
  - не больше 2 чанков с одного источника;
  - почти-дубли уже выбранных отсеиваются (шинглы, Jaccard > 0,6);
  - в промпт идут заголовок и текст чанка, без служебных полей (🟡 `format_retrieval_line` заменить).

### 10.6 Шлюз `rag/scope.py`

🔵 Единственная точка чтения из Chroma для фич.

```python
@dataclass(frozen=True)
class ProductScope:
    product_id: str                 # ACTIVE_PRODUCT
    include_expert: bool = True     # общий слой _expert
    include_legacy: bool = True     # COURSE_USE_LEGACY_CHUNKS

    def where(self, extra: dict | None = None) -> dict:
        """{"product_id": {"$in": [...]}} + {"legacy": {"$ne": True}} + extra, через $and."""
```

- Методы шлюза: `search_chunks(query, k, lesson_key=None, kinds=None)`, `search_cards(query, k, …)`, `golden_examples(format, k)`. Каждый вызов добавляет фильтр `{"product_id": {"$in": [product_id, "_expert"]}}`, а при `include_legacy=False` ещё и `{"legacy": {"$ne": true}}`.
- Прямые вызовы `collection.query` и `collection.get` из фич запрещены. Существующие `retrieve_for_avatar_task_async` и `format_few_shot_block*` переводятся на шлюз.
- Тест: подменить коллекцию и проверить, что у каждого запроса есть фильтр `product_id`. Запрос без области — исключение.

- Решить с экспертом, какая версия уроков МБТ актуальна (поток 2023 года или новая). Старое положить в `Архив/`.
- Проверить на сервере, что свежий yt-dlp отдаёт субтитры и аудио хотя бы для одного видео эксперта на YouTube. Если эксперт пользуется Vimeo или Kinescope — проверить по одной тестовой ссылке.
- Прогнать `scripts/course_mining_probe.py` на одном уроке и одной практике, показать эксперту карточки и паспорт урока. По качеству и цене выбрать `COURSE_MINING_MODEL`.

**Приёмка:**
- бот стартует только с нужными фичами; посторонние пользователи получают отказ;
- при `ACTIVE_PRODUCT=mbt` запрос на тему, которая есть только в «Курсе Магия», не возвращает её фрагменты;
- тест шлюза проходит: у каждого запроса к Chroma есть фильтр `product_id`;
- проверка yt-dlp пройдена или выбран обходной путь;
- эксперт одобрил формат карточек.

### Этап 1. Приём и обработка материалов (5–7 дней)

- Миграция 020.
- `disk_layout.py`, `disk_scan.py`, `course_disk_sync.py`, команда `/sync`.
- `course_intake.py`, `classify.py`, `video_hosts/` (ytdlp, disk_media), `subtitles.py`, `transcribe.py`.
- `documents.py`: PDF, слайды, DOCX, TXT, vision.
- `worker.py`, индексация чанков по схеме v2, команды `/lessons` и `/queue`.

**Приёмка:**
- Папка «Урок 2.4. …» с конспектом и слайдами на Диске → после опроса и обработки в `/lessons` у урока 2.4 отмечены ✅ конспект и ✅ слайды, PNG слайдов на месте.
- Файлы папок неактивных продуктов не попадают в `course_sources`.
- Ссылки на запись урока и на практику → карточка подтверждения с правильными уроком и типом. На 10 тестовых ссылках не меньше 8 определены без правок. После подтверждения появляется расшифровка с таймкодами.
- Видео в `Эфиры/` на Диске → расшифровка с таймкодами.
- То же видео урока на YouTube и на Диске распознаётся как дубль и повторно не обрабатывается.
- Повторная синхронизация ничего не переобрабатывает; изменённый файл переобрабатывается; удалённый исчезает из поиска.
- Рестарт бота посреди обработки не теряет и не дублирует источники.

### Этап 2. Разбор и голос (3–5 дней)

- Миграции 021 и 023.
- `mining.py`: карточки, склейка дублей, частота, проверка цитат; паспорт урока.
- `style.py`, первое наполнение золотого фонда, коллекция `content_cards`.
- Команды `/lesson`, `/bank`, `/style`.
- Шаг 2 миграции Chroma (§10.7).

**Приёмка:**
- На тестовом уроке паспорт содержит все разделы, карточек 20–30 на час видео.
- В выборке из 10 карточек минимум у 8 цитата дословная, а ссылка с таймкодом ведёт в нужное место (±15 с).
- В 20 карточках из практик нет имён и узнаваемых деталей участников.
- Паспорт голоса собран из постов. Своя версия эксперта загружается, и автопересборка её не перезаписывает.
- После загрузки МБТ в поиске нет старых чанков МБТ; у всех новых чанков есть `source_id`, `lesson_key` и заголовок.

### Этап 3. Черновики (4–6 дней)

- Миграция 022.
- `formats.py`, `writer.py`, `content_prompts.py`.
- `content_studio.py`: черновики, кнопки, правки ответом (текстом и голосом), 👍/👎, «Опубликовал», альбом слайдов.
- Дайджест «Из свежей практики», режим «по запросу».

**Приёмка:**
- Черновик каждого формата укладывается в его требования.
- Правка ответом (текстом и голосом) даёт новую версию, история версий сохраняется.
- Одобренный (👍) текст попадает в золотой фонд активного продукта и используется как образец в следующем черновике того же формата.
- После обработки практики эксперту приходит дайджест, и кнопки в нём создают черновики.
- Свободный запрос со ссылкой на урок («пост по уроку 2.4 про …») опирается на материалы этого урока.

### Этап 4. План недели (2–3 дня)

- `planner.py`, расписание, команды `/plan` и `/focus`, переключатели, «Написать выбранные».
- Учёт использования карточек, правила из 👎 → паспорт голоса.

**Приёмка:**
- План приходит по расписанию.
- Соблюдён `CONTENT_PLAN_MIX`, не больше 3 позиций на урок.
- Карточка не повторяется раньше чем через `CARD_REUSE_DAYS` дней.
- Фокус учитывается в заходах.

### После MVP

- **Этап 5:**
  - Kinescope (API);
  - закрытые видео YouTube и Vimeo;
  - команда `/product` для переключения продукта;
  - мини-апп (банк идей, календарь);
  - публикация в Telegram-канал по кнопке;
  - скриншоты постов в `Посты/` (vision);
  - очистка `data/course/` у удалённых источников.

  - вертикальные клипы из видео уроков (🟡 `K/telemost_shorts/ffmpeg_render.py`, `K/telemost_shorts/moments_llm.py`);

## 14. Риски и расходы

| Риск | Что делаем |
|---|---|
| Материалы одного продукта попадают в тексты другого | реестр, `ACTIVE_PRODUCT`, шлюз `rag/scope.py` с тестом; обрабатывается только папка активного продукта |
| YouTube блокирует yt-dlp на серверных IP. В сохранённых логах Кости нет ни одной успешной загрузки с YouTube, версия yt-dlp — мартовская | проверка на этапе 0; обновление yt-dlp при деплое; cookies; официальный API от имени владельца; видео на Диск как запасной вариант |
| Kinescope не поддерживается yt-dlp | API Kinescope по токену (этап 5); до этого — YouTube или Диск |
| Большие видео на Диске: время, место, платная расшифровка | приоритет YouTube; поиск дублей по длительности; лимит `COURSE_MEDIA_MAX_GB`; оценка перед запуском |
| Две версии уроков МБТ (поток 2023 года и новая) | решение эксперта на этапе 0, старое в `Архив/`; `superseded_by`; отсев почти-дублей при сборке контекста |
| Автосубтитры без пунктуации и с ошибками в терминах | для разбора этого достаточно; цитаты проверяются на дословность; при низкой плотности субтитров — Whisper |
| В практиках не разделены спикеры | LLM различает по смыслу, имя эксперта есть в промпте. Карточки практик используются как темы, а не как цитаты эксперта |
| Утечка личных историй участников | обезличивание при разборе; окна практик не идут в генерацию; публикация только вручную |
| Искусственный, «пластиковый» текст | паспорт голоса; золотой фонд с первого дня (посты эксперта); правила из 👎; около 2 недель на настройку |
| Повторы тем | `last_used_at`, `CARD_REUSE_DAYS`, лимит позиций на урок в плане |
| Рост расходов | `/costs`, оценка перед массовой обработкой, лимиты vision и карточек |

**Ориентир по расходам** (порядок величин; цены сверить на старте). Для примера возьмём продукт примерно на 55 часов видео: 12 уроков по 1,5 часа и 25 практик по 1,5 часа.

| Статья | Разово | В месяц |
|---|---|---|
| Расшифровка | $0 на субтитрах YouTube; около $20, если всё через Whisper | $0–3 на новые практики и эфиры |
| Видео и аудио с Диска | около $0,36 за час (всегда Whisper) | по факту |
| Разбор в карточки | около $1–5 | копейки |
| Эмбеддинги | меньше $0,1 | около 0 |
| Генерация (~150 черновиков с правками) | — | около $1–5 |
| Сервер | — | тот же VPS, что у Кости |

## Приложение Б. Сценарии

1. **Новый урок.**
   - Помощник создаёт на Диске папку «МБТ/Курс/Модуль 2/Урок 2.7. …» и кладёт туда конспект и слайды.
   - В течение 15 минут бот разбирает материалы и сообщает эксперту: «Урок 2.7 разобран: паспорт + 18 карточек».
   - Эксперт присылает ссылку на запись урока на YouTube. Бот спрашивает: «МБТ · Урок 2.7 · запись урока?» [✅].
   - Минут через десять: «Урок 2.7: + 31 карточка из видео».
2. **Практика.**
   - Эксперт присылает ссылку на запись Zoom. Бот спрашивает: «Урок 2.4 · практика · 18.09?» [✅].
   - Минут через 15 приходит дайджест «6 тем для контента».
   - Эксперт нажимает [🎬 Рилс] у темы 2 и получает черновик.
   - Отвечает голосовым: «сделай хук жёстче и убери последний абзац». Приходит новая версия, эксперт ставит 👍.
3. **Эфир на Диске.**
   - Помощник кладёт запись эфира в «МБТ/Эфиры/2026-09-25 Эфир про сепарацию.mp4».
   - Бот показывает оценку («1 ч 10 мин, расшифровка около $0,42») с кнопкой [▶️ Запустить].
   - После обработки приходит дайджест с темами для контента.
4. **Понедельник.**
   - В 09:00 приходит «МБТ · план на 22–28.09» из 7 позиций. Эксперт снимает две и нажимает [✍️ Написать выбранные].
   - Приходят 5 черновиков. Эксперт их правит, одобряет (👍) и после публикации нажимает [📌 Опубликовал].
5. **Свободный запрос.**
   - Эксперт пишет: «Нужен пост про то, почему после урока 2.10 про сепарацию люди бросают практику».
   - Бот находит карточки только МБТ (вопросы из практик, урок 2.10) и присылает черновик.
